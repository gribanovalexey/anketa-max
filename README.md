# Анкета в MAX → Google Таблица

Схема работы:

```
Пользователь нажимает «Старт» в чате с ботом
   │
   ▼
Бот: «Поделитесь номером» [📱 Поделиться контактом] ──▶ лист «Контакты»
   │
   ▼
Бот: «Заполните анкету» ──▶ Мини-приложение (docs/, GitHub Pages)
                                │  POST: ответы + initData (подпись MAX)
                                ▼
                    Google Apps Script (google-apps-script/Code.gs)
                    проверяет подпись → строка в листе «Ответы» (+ телефон из «Контактов»)
```

Отдельный сервер не нужен: и бота, и запись в таблицу обслуживает бесплатный Google Apps Script.

Бот работает в одном из двух режимов:
- **webhook** (`setupWebhook`) — MAX сам присылает события в скрипт, бот отвечает сразу.
  Документация MAX требует ответ 200, а Apps Script отвечает переадресацией 302, поэтому
  скрипт отсеивает повторные доставки, а функция `webhookStatus` показывает, не отключил ли MAX подписку;
- **опрос** (`setupBot`, запасной) — бот сам забирает события раз в минуту, отвечает с задержкой до минуты.

## Структура

| Файл | Что это |
|---|---|
| `docs/config.js` | **Вопросы анкеты и адрес скрипта** — редактируется под вашу анкету |
| `docs/index.html`, `app.js`, `style.css` | Мини-приложение |
| `google-apps-script/Code.gs` | Бот (запрос контакта), приём ответов и запись в таблицу |

## Шаг 1. Бот в MAX

1. Подключить организацию / ИП / самозанятого на платформе для партнёров:
   <https://business.max.ru/self> (подключение ботов и мини-приложений доступно только им).
2. Создать чат-бота и скопировать **токен бота** — он понадобится на шаге 2.

## Шаг 2. Google Таблица и скрипт

1. Создать новую Google Таблицу.
2. **Расширения → Apps Script**. Удалить содержимое `Code.gs` и вставить код из
   `google-apps-script/Code.gs`. Сохранить.
3. **Настройки проекта (⚙) → Свойства скрипта → Добавить свойство**:
   - `BOT_TOKEN` = токен бота MAX
   - (необязательно) `SHEET_NAME` = имя листа, по умолчанию `Ответы`
   - (необязательно) `REQUIRE_CONTACT` = `false` — разрешить заполнять анкету без номера телефона
4. Выбрать функцию `testWrite` → **Выполнить** → выдать доступ к таблице.
   В таблице появится лист «Ответы» с тестовой строкой (её можно удалить).
5. **Начать развертывание → Новое развертывание → тип «Веб-приложение»**:
   - Запуск от имени: **Я**
   - Доступ: **Все** (Anyone)
6. Скопировать **URL веб-приложения** (`https://script.google.com/macros/s/…/exec`).
7. **Запустить бота:** выбрать функцию `setupWebhook` → **Выполнить** → снова выдать доступ
   (скрипту нужны внешние запросы и триггеры). В журнале появится «Готово: MAX присылает события на …».
   - Если появится ошибка «Не удалось определить адрес веб-приложения» — добавить свойство
     скрипта `WEBAPP_URL` = URL из п. 6 и запустить ещё раз.
   - Через день-два запустить `webhookStatus`: если написано «Подписок нет», значит MAX отключил
     webhook — перейти на запасной режим: запустить `setupBot` (опрос раз в минуту).

> После любого изменения `Code.gs` нужно: **Начать развертывание → Управление развертываниями →
> ✏ → Версия: новая → Развернуть** (URL останется прежним).

## Шаг 3. Настроить анкету

Открыть `docs/config.js`:

- в `endpoint` вставить URL из шага 2.6;
- заменить вопросы в `questions` на свои. Типы: `single`, `multi`, `text`, `textarea`,
  `scale`, `phone`, `email`, `number`, `date`, `matrix` (таблица «один ответ в каждой строке», каждая строка — отдельная колонка в Google Таблице); у `multi` есть `max` (не больше N ответов) и `exclusive` (вариант, снимающий остальные). Телефон спрашивать не нужно — его присылает бот. `required: false` — необязательный вопрос,
  `other: true` — вариант «Другое» со своим ответом;
- `allowResubmit: true` — если один человек может заполнять анкету несколько раз.

Колонки в таблице создаются сами по заголовкам вопросов. Если позже добавить вопрос —
добавится новая колонка; переименованный вопрос станет новой колонкой.

## Шаг 4. Разместить мини-приложение (нужен HTTPS)

Проект лежит на GitHub: <https://github.com/gribanovalexey/anketa-max>, мини-приложение — в папке `docs/`.

Включить GitHub Pages: **Settings → Pages → Build and deployment → Source: Deploy from a branch →
Branch: `main`, папка `/docs` → Save**. Через 1–2 минуты анкета будет доступна по адресу
<https://gribanovalexey.github.io/anketa-max/> — эту ссылку и нужно указать в настройках бота MAX.

После изменения `docs/config.js` изменения нужно отправить на GitHub (`git commit` + `git push`
или правка файла прямо на github.com) — сайт обновится сам.

Вместо GitHub Pages можно использовать любой статический хостинг с HTTPS (Яндекс Object Storage,
VK Cloud, Netlify и т. п.) — загрузить туда **содержимое** папки `docs/` (4 файла).

Проверить в обычном браузере: `https://…/?debug=1` — анкета откроется (отправка без MAX
работать не будет — это защита). Без `?debug=1` появится сообщение «Откройте анкету в MAX».

## Шаг 5. Подключить мини-приложение к боту

<https://business.max.ru/self> → **Чат-боты → Перейти** → ваш бот → **⋮ → Настройки** →
вставить ссылку на мини-приложение → выбрать надпись кнопки (**Открыть** / **Старт**) → **Сохранить**.

В чате с ботом появится кнопка запуска анкеты. Ссылку на бота можно рассылать участникам.

## Что попадает в таблицу

Лист **«Ответы»**:
`Дата и время | ID пользователя MAX | Имя | Фамилия | Username | Телефон | <вопрос 1> | …`

Лист **«Контакты»** (заполняет бот): `Дата и время | ID пользователя MAX | Имя | Телефон | Подтверждён MAX`.
«Подтверждён MAX = да» — номер привязан к аккаунту MAX (проверена подпись `hash`).
Если человек не поделился номером, анкета покажет «Сначала поделитесь номером»
(отключается свойством `REQUIRE_CONTACT` = `false`).

Имя и ID берутся из подписанных данных MAX, подделать их нельзя: скрипт проверяет подпись
`initData` токеном бота ([алгоритм](https://dev.max.ru/docs/webapps/validation)).
Повторное прохождение разрешено (`allowResubmit: true` в `docs/config.js`): каждое прохождение — отдельная строка, после отправки есть кнопка «Пройти ещё раз». Чтобы запретить повтор — поставить `false`.

## Тест без MAX

Чтобы проверить запись в таблицу из обычного браузера, временно добавить свойство скрипта
`ALLOW_DEBUG` = `true` и открыть `https://…/?debug=1`. **После проверки удалить это свойство.**

## Если что-то не работает

- **«Подпись не совпала»** — неверный `BOT_TOKEN` (без пробелов, токен именно этого бота).
- **«Нет связи с сервером»** — неверный `endpoint`, либо при развертывании не выбран доступ «Все».
- **Изменения в Code.gs не действуют** — не создана новая версия развертывания.
- **Бот не отвечает на «Старт»** — запустить `webhookStatus`. «Подписок нет» — запустить
  `setupWebhook` заново или перейти на `setupBot`. Подписка есть — проверить, что после правки
  `Code.gs` развернута **новая версия**; ошибки смотреть в **Выполнения**.
  В режиме опроса (`setupBot`) ответ приходит с задержкой до минуты.
- **Нет кнопки «Заполнить анкету» в сообщении бота** — MAX не принял кнопку `open_app`; бот
  в этом случае просит нажать «Открыть» внизу чата, анкета всё равно работает.
- **«Подтверждён MAX = нет»** при нажатии кнопки «Поделиться контактом» — пришлите разработчику
  строку из **Выполнения**, нужно уточнить формат подписи.
- Логи скрипта: Apps Script → **Выполнения**.

## Перенос ответов в АРМ СОРУ

Скрипт [`soru/soru_import.py`](soru/soru_import.py) переводит ответы из Google Таблицы в файл для
загрузки в АРМ СОРУ (форма «Стартовая диагностика 1 класс → Анкета родителей»). В базу СОРУ он
ничего не пишет — только создаёт `.7z`, который вы загружаете кнопкой «Загрузить» в программе.
Нужен Python 3 (стандартная библиотека) и Windows (архив собирается штатным `tar.exe`).

1. **Шаблон.** В АРМ СОРУ выгрузите форму «Анкета родителей» класса за **сентябрь 2025** (пустую) —
   в ней список класса с кодами учеников. Например, `3.7z`.
2. **Ответы.** Google Таблица → лист «Ответы» → **Файл → Скачать → CSV** (например, `ответы.csv`).
3. **Сборка файла:**
   ```
   python soru\soru_import.py --csv ответы.csv --template 3.7z --out загрузка.7z
   ```
   Скрипт покажет, сколько анкет сопоставлено с учениками, и перечислит те, где ФИО не нашлось
   (опечатка, «Петя» вместо «Пётр» и т. п.) — с подсказкой «похоже на …». Для таких добавьте
   ручное сопоставление и запустите ещё раз:
   ```
   python soru\soru_import.py --csv ответы.csv --template 3.7z --out загрузка.7z --match "Петров Петя=std_00001234_000000"
   ```
   Если на одного ребёнка пришло несколько анкет, берётся последняя.
4. **Перед загрузкой** сделайте копию `C:\Program Files (x86)\SORU\ASSORUDB.FDB`.
5. В АРМ СОРУ: **Загрузить** → `загрузка.7z`, затем откройте «Стартовая диагностика 1 класс →
   Анкета родителей» и проверьте ответы пары учеников.

Что попадает в СОРУ: вопросы 2–8, 10–13, 17, 19–24, 26, 27 и из вопроса 15 — две причины
(«работа по дому или хозяйству», «позднее засыпание»), так устроена форма СОРУ. Вопросы 1, 9, 14,
15 (остальные причины), 16, 18, 25, 28 в стартовой форме СОРУ отсутствуют и остаются только в Google Таблице.
Коды ответов взяты из справочников самой программы `armsoru.exe`.
